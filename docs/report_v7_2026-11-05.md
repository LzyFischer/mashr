# MAS-HR v7 实验报告：MATH、BIRD-SQL、ALFWorld

> 2026-11-05。代码见 `mashr/`（v7），数据见 `results/v7/{math,bird,alfworld}/`。所有数字都可以从这些目录里的
> `log.txt`、`trace.json`、`test.json`、`costs.json` 和每轮的 `round_N/report.md`、`candidates.json` 查到。
> 每个任务只跑了一个种子（seed 0），dev-B 50 题，结论要按这个样本量来读。

## 1. 设置

**方法（residual harness for harnesses）。** 每道题，meta-agent（Qwen3.5-9B，thinking medium = 2048 token）
先写出一个团队（Python 风格的代码，只解析不执行），并给每个节点分发它这道题的 residual harness：tools 和 skills。
每个 task agent 的完整 harness = 它的 self harness（role，由 evolver 演化）+ meta-agent 给的 residual harness。
task agent 也是 Qwen3.5-9B，不开 thinking。meta-agent 不自己解题。离线的 evolver（Qwen3.8-27B，thinking high，
在 Tinker 上）读 dev-A 上的报告，提出两层修改：

- task-agent 层：增加 / 删除 / 修改一个 task agent 的 role；
- meta-agent 层：增加 / 修改 / 删除 meta-harness 里的一条规则。

每轮 3 个候选：一个只能改 task-agent 层，一个只能改 meta-agent 层，一个两层都能改。dev-B 门控选正确率最高的
（平局时选成本低的）。tools 和 skills 由人手写、固定，evolver 不能改。起点是每个任务手写的种子组织。

**各任务的 harness。**

| 任务 | task agent（种子） | tools（固定） | skills（固定） | 一个节点怎么工作 |
|---|---|---|---|---|
| MATH | solver、coder、verifier | 10 个预加载的 Python 函数（exact_solve、brute_force、number_theory、counting、polynomial…） | 14 条，按题型 | 一次作答；有工具时可以运行一次 Python |
| BIRD-SQL | writer、checker | run_sql、find_values、sample_rows、column_info（作用于该题的数据库） | 12 条，按 SQL 常见错因 | 看 schema + 问题 + evidence，最多运行 5 次 Python，最后给出 SQL |
| ALFWorld | actor、planner | valid_actions、memory、goal_reminder（每一步给行动者的辅助信息） | 9 条，按任务类型 + 搜索顺序 + 动作语法 | 只有被 return 的节点在环境里行动（最多 40 步），其他节点写建议 |

**数据切分。** MATH：dev-A 150 / dev-B 50 / test 156（MATH L4–5，整数答案）。BIRD：dev 1534 题打乱后
dev-A 150 / dev-B 50 / test 300，判分为执行结果一致（BIRD 官方 EX）。ALFWorld：test = valid_unseen 134 局（OOD），
dev-A 150 / dev-B 50 取自 train。

## 3. RSI 的过程

| 任务 | dev-B 每轮（第 0–5 轮） | 被接受的轮次和候选 |
|---|---|---|
| MATH | 86 → 92 → 92 → 92 → 92 → 92 | 第 1 轮、第 3 轮，都是"两层都改" |
| BIRD | 54 → 56 → 56 → 56 → 62 → 62 | 第 1 轮"只改 task-agent 层"（与 meta-agent 层候选同为 56%，成本低者胜），第 4 轮"两层都改" |
| ALFWorld | 82 → 90 → 90 → 90 → 90 → 90 | 第 1 轮，"两层都改" |

5 次接受里 4 次来自"两层都改"的候选。只改 task-agent 层的候选在 ALFWorld 上一直最差（第 1 轮只有 68%）。

**dev-B 和 test 的关系。** MATH 和 ALFWorld 上 dev-B 和 test 同向上升；BIRD 上 dev-B 涨了 8 个点（50 题里多对 4 题），
test 却跌了 2 个点。BIRD 第 4 轮被接受的修改把 writer 的 role 改成一串禁令（"不要 GROUP BY、DISTINCT、额外 join"），
又加了一条"不要给 top_k_ties、ratio_percentage、check_result、evidence_first"，像是照着 dev-A 的几道错题写的。

**最终组织长什么样。**
- MATH：删掉了 coder；solver 的 role 要求能精确计算处用工具、问"所有值"时全部列出、最后代回验证；verifier 改成
  "对抗式"检查，计算类答案用 Python 复算。meta-harness 8 条规则，按题型配 skill，并规定 verifier 必须接输入。
- BIRD：writer / checker 的 role 变成具体的写法和检查清单；meta-harness 加了 skill 的禁用列表和合法代码格式。
- ALFWorld：actor 固定拿 valid_actions + memory + goal_reminder；每局都配 planner，并按任务类型配 skill。

## 4. 发现的问题

1. **meta-agent 不完全遵守规则。** ALFWorld 的 meta-harness 明确写了"planner 必须接到 actor 上，不能并行"，
   test 上仍有 28/134 局写成并行（actor 看不到计划）。MATH 上早先也有 verifier 没接输入的情况。规则写进 prompt
   不等于被执行。
2. **ALFWorld 的"ReAct 无工具"是 0%，可疑。** 最可能是不看合法动作列表时命令格式全错（环境只回 Nothing happens），
   轨迹没有回查，这个 baseline 暂不使用。
3. **meta-agent 很贵。** MATH 上每题 3.2k，占总成本一半以上：thinking 里它多半仍在解题。按当前要求，prompt 里不提成本。
4. **工具和 skill 用得少。** MATH 冒烟测试里 10 个工具有 6 个、12 条 skill 有 9 条从未被分发，报告里会列出"从未给过"的条目。
5. **允许 meta-agent 直接作答会伤难题。** 一个早期版本允许 `return answer(...)`：简单题它直接作答，难题自己写代码解题、
   写超长度后落到兜底方案（dev-B 8/50 兜底）。现在已禁止它解题（结果保留在 `results/v7/math_direct_answer_aborted/`）。
6. **磁盘泄漏（已修复）。** TextWorld 每创建一个环境就复制一份 35 MB 的 `libdownward.so` 并加载，删掉的副本在进程退出前一直占着磁盘，
   导致 ALFWorld 前两次运行写满根分区崩溃（`results/v7/alfworld_crashed_disk_full{,_2}`）。现在库实例在环境间复用，
   同时存活的环境最多 96 个。

## 5. 时间和 token（三个任务同时在一张 GPU 上跑，互相拖慢）

| 阶段 | MATH | BIRD | ALFWorld |
|---|---|---|---|
| 第 0 轮 dev-B | 2.0 min | 10.4 min | 3.1 min* |
| dev-A 评估（5 轮） | 23.5 min | 14.8 min | 42.1 min* |
| evolver 提案（27B） | 10.6 min | 7.0 min | 7.7 min |
| dev-B 门控 | 40.7 min | 25.1 min | 44.6 min |
| test | 17.1 min | 11.1 min | 81.0 min |
| **合计** | **1.57 h** | **1.14 h** | **2.98 h** |
| 9B 生成 / 输入 token | 8.7M / 11.7M | 3.9M / 11.9M | 3.1M / 52.7M* |

\* ALFWorld 是崩溃后重启的，前两轮大多直接从缓存读出，这两项的 token 偏少。ALFWorld 的输入 token 很多，因为每一步都要重发整段对话；
test 慢是因为 TextWorld 不是线程安全的，环境操作只能排队执行。

## 6. 结论和下一步

- 最站得住的结论：**按题组队并分发 residual harness 这件事本身很有用**。在需要多步交互的任务上（ALFWorld +34 个点，BIRD +4.3 个点）
  优势明显；在 MATH 上与固定架构持平。
- **RSI 的作用还不确定**：+4.5、−2.0、+3.0，幅度小、只有一个种子，BIRD 上还出现了 dev-B 过拟合。
- 下一步候选：加大 dev-B（如 150 题）或多跑几个种子；修 meta-agent 的连线错误（解析时检查、或让 evolver 看到违规次数）；
  借鉴 AHE 的 Agent Debugger，让 evolver 看到每道错题的根因分析；ALFWorld 把环境放到独立进程里提速。
